================================================================================
  DOĞALGAZ TEKLİF FİYATLANDIRMA — iOS / COMPOSE MULTIPLATFORM GEÇİŞ YOL HARİTASI
================================================================================

Bu dosya, mevcut Android (View/XML tabanlı) uygulamasının BİREBİR AYNISINI ayrı
bir Compose Multiplatform (CMP) projesinde yeniden oluşturmak ve oradan iOS /
App Store çıktısı almak için hazırlanmış tam talimat + yol haritasıdır.

Bu dosya, YENİ AÇILAN CMP PROJESİNİN köküne konulmak üzere yazılmıştır. Amaç:
projeyi devralan kişi (veya AI asistan) bu tek dosyayı okuyarak uygulamanın ne
olduğunu, hangi ekranlardan/mantıktan oluştuğunu, neyin ortak modüle taşınıp
neyin sıfırdan yazılacağını ve hangi sırayla ilerleneceğini eksiksiz anlasın.

Son güncelleme: 2026-07-13

0) ÖZET — TEK PARAGRAF
================================================================================

"Doğalgaz Teklif Fiyatlandırma", doğalgaz tesisat ustaları/firmaları için
müşteri yönetimi, 7 adımlı teklif hazırlama sihirbazı, malzeme/fiyat listeleri,
alacak defteri (grafiklerle) ve xlsx yedekleme içeren; verisini tamamen
cihaz-yerel SharedPreferences JSON olarak tutan (DB YOK), Play'de ücretsiz ama
7 günlük cihaz-yerel deneme VEYA Google Play aboneliğiyle açılan bir Android
uygulamasıdır. Bu proje onu CMP'de yeniden yazacak: ortak Kotlin mantık modülü +
Compose Multiplatform UI + platforma özel katmanlar (depolama, dosya seçici,
faturalandırma). iOS'ta faturalandırma StoreKit ile SIFIRDAN yazılır.

    - SharedPreferences → expect/actual KeyValueStore soyutlaması (bkz. bölüm 5).
    - ZIP okuma/yazma (xlsx): Android'in java.util.zip'i JVM'de var ama iOS'ta
      yok → expect/actual "Zip" soyutlaması veya korrelasyonel bir KMP zip lib
      (örn. okio tabanlı) kullan.

COMPOSE'DA SIFIRDAN YAZILIR:
  - 19 ekranın tamamı (bölüm 3) — XML/Fragment yok, hepsi @Composable.
  - RecyclerView adapter'ları → LazyColumn/LazyRow item composable'ları.
  - ViewPager2 (Materials, QuoteMaterials) → HorizontalPager + TabRow.
  - BottomSheet'ler (CustomerFormSheet, indirim, ödeme) → ModalBottomSheet.
  - Dialog'lar (disclaimer, anlaşma metni, liste adı, malzeme düzenle) → AlertDialog.
  - Özel View'lar (ColumnChart, DonutChart, CircleCrop) → Compose Canvas.
  - Navigasyon (3 nav graph) → Compose Navigation veya Voyager/Decompose.

PLATFORMA ÖZEL (expect/actual — androidMain + iosMain):
  - Kalıcı depolama (KeyValueStore).
  - Dosya seçici + dosyaya yazma (yedek xlsx export/import).
  - Görsel seçici + PNG kaydetme (firma logosu).
  - Paylaşım (teklif çıktısı paylaşımı — Android Intent / iOS UIActivityViewController).
  - Faturalandırma (Android Play Billing / iOS StoreKit 2). Bkz. bölüm 7.

5) VERİ KATMANI — DEPOLAMA MODELİ
================================================================================

TEMEL GERÇEK: DB YOK. Tüm veri, SharedPreferences dosyalarında JSON string olarak
tutulur. CMP'de bunun karşılığı: platforma özel key-value store + JSON serileştirme.

SHAREDPREFERENCES STORE'LARI (adları ve içerikleri — yedek uyumu için önemli):
  rota_prefs           → firma adı, logo yolu, birim oranlar, çeşitli ayarlar
  rota_customers       → müşteriler
  rota_ledger          → alacak defteri (receivables)
  rota_quotes          → teklifler
  rota_material_lists  → malzeme listeleri
  rota_price_overrides → fiyat override'ları
  (Firma logosu ayrıca dosya olarak: filesDir/company_logo.png)

NOT: Store adları "rota_" ön ekiyle başlar (eski proje adından kalma). Bunları
DEĞİŞTİRME — yedek dosyaları bu adlarla "store | key | value" satırları tutar.

CMP KARŞILIĞI:
  - commonMain'de: interface KeyValueStore { getString/putString/remove/getAllKeys... }
  - androidMain: SharedPreferences ile actual.
  - iosMain: NSUserDefaults (küçük veri) veya dosya tabanlı JSON store ile actual.
    (Büyük JSON'lar için NSUserDefaults yerine Documents dizininde dosya önerilir;
    yine de "store | key | value" mantığını koru ki yedek round-trip'i bozulmasın.)
  - Logo: iOS'ta Documents/company_logo.png; expect/actual "logo kaydet/oku".
  - Multiplatform hazır alternatif: "multiplatform-settings" kütüphanesi
    (com.russhwolf:multiplatform-settings) — SharedPreferences/NSUserDefaults'u
    tek API altında toplar; başlangıç için en hızlı yol.

6) XLSX YEDEKLEME / GERİ YÜKLEME — EN KRİTİK KALEMLERDEN BİRİ
================================================================================

Mevcut sistem (BackupManager + XlsxWriter + XlsxReader), Apache POI KULLANMADAN
elle .xlsx (OpenXML ZIP) üretir/okur. Bu mantık taşınabilir; SADECE ZIP ve
dosya I/O platforma özeldir.

YEDEK DOSYASI YAPISI (birebir korunacak):
  - Gerçek .xlsx (ZIP). İnsan-okur sayfalar: Özet, Müşteriler, Teklifler,
    Alacak Defteri.
  - Makine sayfası: "Yedek" — her SharedPreferences girdisi bir satır:
        store | key | Base64(value)
    A1 hücresinde işaret: FIYATLA_BACKUP
    Ayrıca "__LOGO__" satırı: Base64(PNG) olarak firma logosu.
  - Base64 kullanımı, hücre içi XML-escape sorunlarını tamamen ortadan kaldırır.

GERİ YÜKLEME AKIŞI (XlsxReader.readSheet(input, "Yedek")):
  1. FIYATLA_BACKUP işaretini doğrula (yoksa reddet).
  2. 6 store'u temizle.
  3. Anahtarları yeniden yaz.
  4. Logoyu geri yükle.
  5. Disclaimer'ı "kabul edildi" olarak işaretle.

CMP'DE YAPILACAK:
  - XlsxWriter/XlsxReader mantığı commonMain'e taşınır; string/ByteArray üretir.
  - ZIP paketleme/açma expect/actual (JVM: java.util.zip; iOS: minizip / okio
    tabanlı KMP zip veya SSZipArchive köprüsü). En az riskli yol: saf-Kotlin bir
    KMP zip implementasyonu kullanmak.
  - Dosya seçici / kaydetme: expect/actual.
      * iOS export: UIDocumentPickerViewController (kaydetme) veya "share sheet".
      * iOS import: UIDocumentPickerViewController (açma), .xlsx UTI izni.
  - ROUND-TRIP TESTİ ZORUNLU: Android'deki XlsxRoundTripTest.kt'nin CMP karşılığını
    commonTest'te yaz — yedek al → geri yükle → veri birebir aynı olmalı.

8) MODÜL / PROJE YAPISI (ÖNERİLEN — CMP)
================================================================================

Yeni CMP projesi (Android Studio → New Project → Kotlin Multiplatform / Compose
Multiplatform şablonu, veya JetBrains Compose Multiplatform Wizard):

  proje-kök/
   ├─ shared/                     (Kotlin Multiplatform kütüphane modülü)
   │   ├─ commonMain/
   │   │   ├─ data/               ← 17 mantık dosyası (taşınacak, temizlenecek)
   │   │   ├─ domain/             ← EntitlementManager, hesaplamalar
   │   │   ├─ ui/                 ← Compose ekranlar (19 ekran) + bileşenler
   │   │   └─ platform/           ← expect: KeyValueStore, FilePicker, Sharer,
   │   │                            LogoStore, Zip, BillingClient
   │   ├─ androidMain/            ← actual: SharedPreferences, Intent, Play Billing
   │   └─ iosMain/                ← actual: NSUserDefaults/dosya, DocumentPicker,
   │                                UIActivityViewController, StoreKit köprüsü
   ├─ androidApp/                 (opsiyonel — CMP Android host; şart değil)
   └─ iosApp/                     (Xcode projesi — Mac'te; SwiftUI host + StoreKit)

Bağımlılık önerileri:
  - Compose Multiplatform (UI)
  - kotlinx.serialization (JSON)
  - kotlinx.coroutines
  - Navigation: Compose Navigation Multiplatform veya Decompose/Voyager
  - multiplatform-settings (KV store) — hızlı başlangıç
  - Zip: saf-Kotlin KMP zip veya okio tabanlı çözüm
